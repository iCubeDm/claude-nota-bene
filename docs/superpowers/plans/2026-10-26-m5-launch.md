# M5 Launch & Self-hosting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user opens the rebuild with `/nb` from Claude Code, exactly as they open the prototype today. After that the prototype is retired.

What this milestone delivers:
- a `nota-bene` launcher with a supervised full restart;
- one window per folder;
- `new` / `fork`;
- the user's prototype state carried over;
- dev mode isolated from the working window;
- the deferred polish from M3/M4 that users hit daily.

**Architecture:**
- **`bin/nota-bene.mjs`** is a small Node supervisor:
  - it parses the arguments;
  - it builds `web/dist` when it is stale;
  - it spawns the server child with `NOTA_BENE_SUPERVISED=1`;
  - it relaunches the child with `--continue` on exit code 75 and after crashes (giving up at 5 crashes in 60 s);
  - it registers the window in `~/.nota-bene/windows.json`.
- **The `/nb` skill** (`skill/` in the repo, symlinked as `~/.claude/skills/nb` at switch-over) brings up the window already serving the folder, or launches the bin detached on a free port in 4777–4799.

**Tech Stack:** as M4. No new dependencies; the launcher uses `node:child_process`.

**Spec:** `docs/superpowers/specs/2026-10-24-nota-bene-rebuild-design.md`, sections "Parity checklist → Launch & self-hosting (M5)" and "↻" (R-M4-1).

**Reference:** read only:
- `prototype/ide.sh`: the supervisor loop, exit codes and crash guard;
- `prototype/skill/SKILL.md` and `prototype/skill/open.sh`: argument aliases, the guards, port probing, the `NB:` output contract, the last-session check;
- `prototype/server.mjs`: `--fork` with `forkSession`, `.sessions.json`.

**Base:** branch `m5-launch` from `main` (86ab7d1).

## Global Constraints

- The M0–M4 rules still hold:
  - one task is one small commit with What / Why / Verified by and the trailer `Task: M5-NN`;
  - every UI string goes through `t()` in ru and en;
  - no state in the repo;
  - ports: 4790 for smoke runs, 4791–4795 for e2e, never 4777–4781 for tests.
  - Smoke runs use temp `NOTA_BENE_HOME` and `CLAUDE_JOURNAL_VAULT`, and their transcripts go to the Trash afterwards.
- The live window range stays **4777–4799**, the same as the prototype. During the transition both apps may hold ports there; `/info.root` tells them apart.
- The launcher exit codes follow `prototype/ide.sh`:
  - 75 relaunches immediately with `--continue`;
  - 0, 130 and 143 exit;
  - any other code is a crash: relaunch after 1 s, and give up at 5 crashes within 60 s.
- Rulings:
  - **R-M5-1.** ↻ keeps restarting the agent (R-M4-1). The full server restart is a second action in the ↻ menu, shown only when `/info.supervised` is true.
  - **R-M5-2.** Dev mode never touches the working state. `npm run dev` defaults `NOTA_BENE_HOME` to `~/.nota-bene-dev`, on ports 4780 and 5173 as today.
  - **R-M5-3.** The prototype is retired, not deleted. `prototype/` stays in the repo as an archive and reference. Retiring means:
    - the `/nb` symlink points to the rebuild;
    - the local root compat symlinks are removed;
    - the docs say so.
  - The switch of the user's `~/.claude/skills/nb` symlink is done only after the user confirms in chat.
  - **R-M5-4.** Prototype state is imported once, idempotently:
    - `prototype/.sessions.json` folder→session entries become `sessions.json` entries, unless the rebuild already has one for that folder;
    - `_mode:<port>` combined with `_root:<port>` becomes `prefs.modes[root]` (same rule).
    - A marker in `prefs.json` (`importedPrototype: true`) prevents a re-run.

## Review Focus

1. **Two `/nb` calls on the same folder at the same moment.** Exactly one server must end up serving the folder, and the second call must report "already open". Port binding is the arbiter: the loser's server fails to bind or finds the folder registered, and its launcher exits cleanly. Test in M5-04.
2. **Stale `windows.json` entries.** This covers a killed process, a port reused by another app, and a prototype window on that port. Every entry is verified with `/info.root` (and the pid is checked to be alive), and stale ones are pruned. A wrong window is never brought to front. Test in M5-02 and M5-04.
3. **Exit codes and signals.**
   - Ctrl-C and SIGTERM to the launcher stop the child and exit without a relaunch.
   - A child killed by a signal counts as a crash.
   - 75 relaunches with `--continue` and the same port, so the open browser tab reconnects by itself.
   - Test in M5-02.
4. **`--fork` never appends to the source transcript.** The window gets a new session id, and the terminal's session stays untouched. Test in M5-01, plus a real check in the M5-10 smoke.
5. **The migration never overwrites newer rebuild state**, and it runs once. A corrupt or missing prototype file is skipped silently. Test in M5-05.

### M5-01: Server launch options

**Files:** Modify `server/src/main.ts`, `server/src/session.ts` (fork), `server/src/agent/{types,sdk,fake}.ts`, `server/src/http.ts`/`server.ts`, and their tests.

**Interfaces:**
- CLI: `node server/src/main.ts [dir] [--port N] [--resume ID [--fork]] [--new] [--continue] [--fake script] [--allow-origin O]`.
  - **Default, with no `--resume` or `--new`:** resume `lastSession(dir)`, but only if its transcript still exists (check `~/.claude/projects/*/<id>.jsonl` the way the prototype's open.sh does). Otherwise start a new session. `--continue` keeps its meaning and is the same as the default.
  - **`--new`** always starts a new session.
  - **`--resume ID --fork`** passes `resume: ID, forkSession: true` to the SDK. The new session id comes from init, and only that new id is saved.
- **`/info`** gains `supervised: process.env.NOTA_BENE_SUPERVISED === '1'`.
- **`POST /restart-server`:**
  - Origin-checked (non-GET);
  - answers 409 when not supervised;
  - otherwise answers 200, flushes, closes the agent, then exits with code 75 after 100 ms.
- **AgentBackend.start** gains `fork?: boolean`. The fake records it and gives the forked session a new id.

- [ ] **Step 1: Failing tests:**
  - the default resumes the saved session when its transcript exists, and starts new when it does not;
  - `--new` ignores the saved session;
  - `--fork` starts with `fork: true`, then saves the new id and not the source id;
  - `/info.supervised` follows the env;
  - `/restart-server` gives 409 unsupervised and 403 for a foreign Origin; supervised, it calls `process.exit(75)` (stub `exit`).
- [ ] **Step 2–4.** **Step 5: Commit** `feat(server): launch options, fork and supervised restart`.

### M5-02: The `nota-bene` launcher

**Files:**
- Create: `bin/nota-bene.mjs`, `server/src/windows.ts` and their tests.
- Modify: root `package.json` (the `bin` field).

**Interfaces:**
```ts
// windows.ts — ~/.nota-bene/windows.json: { [port: string]: { root: string; pid: number; startedAt: number } }
export function registerWindow(port: number, root: string, pid: number): void;   // atomic, merge
export function unregisterWindow(port: number, pid: number): void;               // only if the pid matches
export function liveWindows(probe: (port: number) => Promise<{ root: string } | null>): Promise<{ port: number; root: string }[]>; // verifies via /info + pid alive, prunes stale
```
- **Launcher behaviour.** `nota-bene [dir] [--port N] [--resume ID [--fork]] [--new] [--detach] [--no-open]`:
  - It refuses `$HOME` and `/` with the prototype's message.
  - It realpaths `dir`.
  - When `--port` is absent, it takes the first free port in 4777–4799, checked with a real bind test, not `nc`.
  - It builds `web/dist` when it is missing or older than any file under `web/src`, `web/index.html` or `shared/src` (mtime). The build runs `npm run build -w web` in the repo.
  - It spawns the server with `NOTA_BENE_SUPERVISED=1` and the args, registers the window after `/info` answers, and unregisters it on exit.
  - It runs the supervisor loop exactly as described in Global Constraints. A relaunch adds `--continue` and drops `--resume`, `--fork` and `--new`.
  - Without `--no-open` and on the first start only, it opens `http://127.0.0.1:PORT` (`open` on macOS, `xdg-open` elsewhere).
  - `--detach` re-spawns itself detached (`nohup` semantics: `detached`, stdio to `${TMPDIR}/nota-bene-PORT.log`), waits up to 20 s for `/info`, prints `URL`, and exits 0. It prints the last 15 log lines and exits 1 on timeout.
- Signals: SIGINT and SIGTERM go to the child; after it exits, the launcher exits with code 0 and never relaunches.

- [ ] **Step 1: Failing tests** (spawn the bin with `--fake`, temp `NOTA_BENE_HOME`, ports 4791–4795):
  - it starts, `/info` answers, and windows.json has the entry;
  - `POST /restart-server` brings the server back on the same port with `--continue`;
  - a child crash relaunches it, and 5 fast crashes give up (inject them with a test-only env var that makes the server exit with 1);
  - SIGTERM stops it without a relaunch and removes the entry;
  - a stale entry (dead pid) is pruned;
  - an entry whose `/info.root` differs is ignored;
  - the dist rebuild is skipped when it is fresh (spy via an env var that points the build at a stub command).
- [ ] **Step 2–4.** **Step 5: Commit** `feat: nota-bene launcher with supervised restart`.

### M5-04: The `/nb` skill

**Files:** Create `skill/SKILL.md`, `skill/open.sh`, `skill/open.test.ts` (it runs open.sh with a temp HOME and fake servers).

**Interfaces:**
- `SKILL.md`: the prototype's SKILL.md, with the same arguments `[new | fork]`, the same `NB:` contract and the same instructions. `allowed-tools: Bash(*/nb/open.sh *)`.
- `open.sh "<args>" <callerSessionId>`:
  - **Arguments:** the same aliases as the prototype (`new|новая|новую|заново`, `fork|continue|here|продолжить|продолжи|форк`). An unknown argument prints the usage line.
  - **Guards:** inside Nota Bene (`NOTA_BENE_SUPERVISED` or `AI_IDE_SUPERVISED` set), print "already running inside Nota Bene". `$HOME` and `/` are refused.
  - **Existing window:** `bin/nota-bene.mjs --find "$DIR"` prints the port of a live window serving the folder, using `liveWindows` + `/info`. As a fallback it probes 4777–4799 `/info` roots, which also finds prototype windows during the transition. On a hit it opens that URL and prints "already open at …". With `fork`, it prints the prototype's "NOT switched" note.
  - **Otherwise it launches:**
    - `last` → `nota-bene "$DIR" --detach`. The server's default resume of the last session applies. The note says resumed or new: read `lastSession` with the bin's `--last "$DIR"` helper, which prints the id if its transcript exists.
    - `new` → `--new`.
    - `fork` → `--resume "$SID" --fork`, with the SID validated as a UUID.
  - **Output:** the prototype's lines, with `NB: opened http://127.0.0.1:PORT for DIR (…)` plus the log path.
