# M1 Comments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The review loop of the prototype, rebuilt on stable anchors. Select a fragment of a reply or of your own message, leave a comment (typed, a quick label, emoji), collect comments in a side panel and send them to the agent as one batch. Pending and sent marks survive reloads, restarts and resumes.

**Architecture:**
- **Comments are server state, keyed by session id.** They are persisted in `~/.nota-bene/comments/<sessionId>.json` and synced to every window as a full set (`comments` event, not part of the replayed history).
- **The web keeps them in a `comments` slice.** It locates them in the DOM only through `web/src/anchors/` (W3C-style TextPosition + TextQuote).
- **A single overlay layer paints the marks.** Components never hold DOM ranges.

**Tech Stack:** as M0 (Node 26 TS, React 19, Redux Toolkit 2.13, Tailwind 4, Vitest 5, Playwright 1.64), plus `emojibase-data` 18.0.0 (emoji list and GitHub shortcodes).

**Spec:** `docs/superpowers/specs/2026-10-24-nota-bene-rebuild-design.md`, sections "Comment anchors" and "Parity checklist → Comments (M1)".

**Base:** branch `m1-comments` from `m0-foundation` (stacked on PR #1 until it merges).

## Global Constraints

Everything in M0's Global Constraints and Commit convention still holds: one task = one small commit with What / Why / Verified by, the trailer `Task: M1-NN`, exact versions, every UI string via `t()` in ru and en, no state in the repo, `prototype/` untouched.

Scope cuts:
- **Comments on files** wait for file tabs (M3).
- **Count badges on tabs and tree rows** wait for M2/M3.
- **Image references in a batch** wait for attachments (M3).

The anchor code must take `AnchorSource` of kind `file` from day one, so M3 only adds the UI.

## Review Focus

1. **A comment on a fragment that later re-renders** (streaming ends; language switch; reload) still highlights the same text or becomes orphaned. It never highlights a wrong fragment. Test in M1-05.
2. **Two windows on the same session.** A comment added in one appears in the other. A batch sent from one marks it sent in both. Test in M1-03.
3. **Keyboard collisions.** Enter, Esc and Tab in the popup, the `:` picker and the composer must not trigger each other: Esc closes the picker before the popup, and the popup's ⌘Enter never sends the chat message. Test in M1-11 and M1-17.
4. **Selection across two items** (from a reply into the next user bubble). The anchor belongs to one source: either the selection is clipped to the start item, or the Comment button does not appear. It is never a broken anchor. Test in M1-09.
5. **A session without an id yet** (fresh session before the first init). Comments are kept in memory and persisted once the id is known, never written to `comments/undefined.json`. Test in M1-02 / M1-03.

### M1-03: Comment sync over the socket

**Files:** modify `server/src/session.ts` (expose the current session id and an "id became known" hook), `server/src/server.ts` (dispatch); test `server/src/comments-sync.test.ts`.

**Behaviour:**
- On attach, after the replay, the server sends `{kind:'comments', items: store.get(id)}`.
- `{type:'comments'}` → `store.set` → broadcast `comments` to all sockets (`store:false`).
- `send` with `commentIds` → `store.markSent(id, commentIds, send.id)` → broadcast.
- When the session id first becomes known (init) → `store.adopt(id)`.
- On resume → load the stored set for that id.

### M1-05: Anchor resolve

**Files:** create `web/src/anchors/resolve.ts`; test `web/src/anchors/resolve.test.ts`.

**Interfaces — produces:**
```ts
export const CONTEXT = 32;
export function makeAnchor(source: AnchorSource, text: string, start: number, end: number): Anchor;   // fills quote/prefix/suffix
export function resolveAnchor(a: Anchor, text: string): { start: number; end: number } | null;
```
Rule (from the spec):
1. Take the slice `start..end`; if it equals `quote`, done.
2. Otherwise find every occurrence of `quote` and score each by the length of its common prefix/suffix context. The best hit wins; a tie goes to the hit nearest the original `start`.
3. Otherwise return null (orphaned).

- [ ] **Step 1: Failing tests:**
  - `exact position wins`;
  - `moved text is found by quote`;
  - `duplicate quotes are disambiguated by context`;
  - `missing quote → null`;
  - `never returns a range whose text differs from quote` (property-style loop over random edits, Review Focus 1).
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** → pass.
- [ ] **Step 5: Commit** `feat(web): resolve anchors by position, quote and context`.
